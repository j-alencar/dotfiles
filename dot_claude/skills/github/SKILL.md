## When to use

Use this skill when you need to work with something (issues, PRs, reviews, comments) that holds state in GitHub.

## Issue tracking

- Tag created or updated issues with
    - one Type,
    - its Project,
    - me as an Assignee,
    - current Status in Project
    - relationships, if existent

    if it doesn't those set properly already.

- Remember to keep the Status and Relationships updated as you go on with your tasks.

- When I still haven't figured some stuff out via grilling I usually have it in Triage.

- When we decide something is ready-for-agent, tag that and set Status in the project to Ready too

- During grilling and before ready-for-agent we use Backlog

- When writing stuff for Issues or PRs, use the /writing skill

## PRs

- If your PR has a related issue, check if it got linked to the issue when you're done with it, and link if not.

- When sent, watch triggered Actions if existent

- Tag as "In review" in the Project if CI passing and it's confirmed that nothing else needs to be done on your end

## Writing

- When you need to update prose that is related to an issue (the issue itself, reviews, comments, commits, PRs, docs, wikis), use the `/writing` skill
